# 音乐检索系统 (Query By Singing/Humming)

本项目为《信号与系统》课程大作业——“基于哼唱片段的音乐检索系统（听歌识曲）”。

## 任务目标

- **基础1**：提取一段简单单音音频的基频（如使用自相关法），生成音高序列。
- **基础2**：给定一小段标准乐谱序列，通过DTW等算法计算哼唱片段与标准序列的相似度。
- **进阶**：建立包含至少10首歌的小型曲库，实现输入哼唱音频并返回最匹配的歌曲。
- **挑战**：提高算法对不同人哼唱（跑调、节奏不准）的容错率，或尝试带伴奏的旋律识别；包装为一个可演示的Demo。

## 数据集说明

本项目在算法开发与评估过程中，使用了 [MIRLab 公开数据集](http://mirlab.org/dataset/public/)。

### 1. 核心数据集：MIR-QBSH
- **说明**：QBSH 是 Query By Singing/Humming 的行业标准缩写。该数据集是国际音乐信息检索评测比赛（MIREX）多年的官方测试集。
- **应用场景**：
  - **对口基础1**：适合单声道音高追踪（Monophonic pitch tracking）与静音/清音/浊音检测，是测试基频提取算法抗噪能力的绝佳素材。
  - **对口基础2 & 进阶**：自带标准答案（Ground Truth / MIDI 序列），可用其直接构建10首歌的小型标准曲库；同时提供大量真实的、带有偏差的人类哼唱样本（WAV 音频），非常适合用来严谨测试 DTW 算法的容错率。

### 2. 挑战备单数据集：MIR-1K (选做)
- **说明**：帮助冲击大作业最高难度——“带伴奏的旋律识别”。
- **应用场景**：音频中包含伴奏。侧重于人声分离 (Singing voice separation) 和音频旋律提取。运行前需先使用分离模型（如 Spleeter）把伴奏与人声剥离，再将被丢入算基频的函数中。

**注意：切勿将完整的数据集塞进 GitHub 仓库！（会导致容量爆表，本项目已通过 `.gitignore` 防止误传）**

推荐下载并解压在与当前项目**平级**的外部目录进行引用：

```text
Music_Recognition/
 ├── MIR-QBSH/           # 核心数据集存放处 (海量 wav 和 midi)
 ├── MIR-1K/             # (可选) 带伴奏数据集存放处
 └── MusicRegcognition/  # 本项目工作区 (当前代码仓库)
      ├── .gitignore
      ├── README.md
      ├── demo_samples/  # 仅存放几个用于大作业评审演示的极微型测试音频
      └── src/           # 源码 
```
